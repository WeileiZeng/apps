# apps

这个仓库只用来发布静态网页。页面在各自的项目里开发和构建，构建结果放进这里的子目录。源码不放进本仓库。

GitHub Pages 从 `main` 分支的根目录发布。站点地址是 [https://weileizeng.github.io/apps/](https://weileizeng.github.io/apps/)。某个页面的地址是 `https://weileizeng.github.io/apps/<名字>/`。

## 仓库里有什么

| 路径 | 作用 |
| --- | --- |
| `index.html` | 主页，列出已经发布的页面 |
| `<名字>/` | 一个页面的构建结果，例如 `qec/` |
| `.nojekyll` | 让 Pages 按原样提供文件，不用 Jekyll 处理 |

当前页面：

| 目录 | 页面 |
| --- | --- |
| `qec/` | 编码演示 |

## 发布流程

1. 在源码项目里构建。页面引用的资源必须是相对路径。Vite 项目先把 `base` 设为 `'./'` 再构建。只用 `dist` 里的文件。
2. 选一个短的英文目录名，例如 `qec`。这个目录已经存在时，用新的构建结果整份替换。
3. 在本仓库执行 `git pull`。
4. 清空 `<名字>/`，再把 `dist` 的内容拷进去。不要和旧文件合并，构建产物的文件名每次都会变。不要拷贝源码、`node_modules` 或 `dist.zip`。
5. 主页还没有这张卡片时，在 `index.html` 的目录列表里按现有卡片的结构加一张，链接指向 `<名字>/`。保留主页现有的版式。
6. 只在本仓库提交并推送 `main`。提交说明写这次放上或更新了哪个页面。
7. 打开 `https://weileizeng.github.io/apps/<名字>/`，确认页面和它引用的 `./assets/` 都能打开。推送之后 Pages 可能要等大约一分钟。

不要改 Pages 的发布设置。不要把源码仓库推到这里。

## 在本机看主页

在仓库根目录起一个静态服务器，再打开它打印的地址：

```sh
uv run python -m http.server 4173
```
